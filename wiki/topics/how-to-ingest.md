# 如何摄入新的源文件

本文说明当 `raw/` 目录下新增文件时，如何触发 LLM 进行摄入处理。

---

## 前提条件

- 在 VS Code 中打开 `lch-wiki` 工作区
- 已开启 GitHub Copilot Chat（`Ctrl+Shift+I`）

---

## 操作步骤

### 1. 放入源文件

将新的源文件复制到 `raw/` 目录下：

```
lch-wiki/
└── raw/
    ├── assets/          ← 图片放这里
    └── 你的新文件.md     ← 源文档放这里
```

**支持的文件格式：** Markdown（`.md`）、PDF（`.pdf`）、图片（`.png` / `.jpg`）等。

> ⚠️ `raw/` 目录是只读区域 — LLM 只读取不修改，保证源文件完整性。

### 2. 告诉 LLM 摄入

在 Copilot Chat 中输入以下命令之一：

```
# 摄入单个文件
请摄入 raw/新文件名.md

# 摄入多个指定文件
请摄入 raw/文件A.md 和 raw/文件B.pdf

# 摄入所有新增文件
请摄入 raw 目录下的文件
```

### 3. LLM 自动执行

LLM 收到指令后会依次执行：

| 步骤 | 操作 | 产出 |
|------|------|------|
| ① | 阅读源文件，提取关键要点 | — |
| ② | 在 `wiki/sources/` 创建摘要页 | `sources/xxx.md` |
| ③ | 创建或更新概念页 | `concepts/xxx.md` |
| ④ | 创建或更新实体页 | `entities/xxx.md` |
| ⑤ | 更新内容索引 | `wiki/index.md` |
| ⑥ | 更新全局综述（如有重要发现） | `wiki/overview.md` |
| ⑦ | 追加操作日志 | `wiki/log.md` |

### 4. 验证结果

摄入完成后，可以通过以下方式验证：

- **查看 `wiki/index.md`** — 确认新页面已出现在索引中
- **查看 `wiki/log.md`** — 确认摄入记录已追加
- **Obsidian 图谱视图** — 查看新页面的交叉引用关系

---

## 常见场景

### 场景 A：追加一个新文件

```
# 1. 复制文件到 raw/
# 2. 在 Chat 中说：
请摄入 raw/MOM平台操作手册.pdf
```

### 场景 B：批量追加多个文件

```
# 1. 将多个文件复制到 raw/
# 2. 在 Chat 中说：
请摄入 raw 目录下的文件
```

LLM 会自动识别哪些是新增文件（对比 `wiki/sources/` 中已有的摘要页）。

### 场景 C：源文件更新了内容

如果 `raw/` 中已有的文件内容发生了变化：

```
raw/xxx.md 内容已更新，请重新摄入
```

LLM 会重新阅读该文件，并**增量更新**相关 Wiki 页面，而非重复创建。

---

## 注意事项

1. **不要修改 `raw/` 下的文件** — 如需修正，替换整个文件而非编辑
2. **一次摄入建议不超过 3-5 个文件** — 确保 LLM 有足够上下文处理每个文件
3. **摄入后可追问** — 如 "这篇文档的核心观点是什么？"，LLM 会基于 Wiki 回答
4. **图片需配合文本** — 单独的图片文件建议放在 `raw/assets/`，并在对应的 Markdown 文件中引用
